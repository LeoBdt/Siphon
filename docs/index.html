Your media,
on your own machine.

A web interface for yt-dlp that you host yourself. Paste a URL, choose a quality, and watch it arrive in a library you actually browse. Your files never leave your machine.

What it does

The parts you end up needing

Not a form around a command line — the whole loop, from pasting a link to finding the file again three weeks later.

For whoever is downloading Paste a link, get the file, find it again later.

Quality you choose

Video with sound up to 4K and 60 fps, or audio on its own. M4A and Opus are lifted straight from the source with no re-encoding, so nothing is lost. MP3 is there when you need compatibility.

Playlists and channels

Paste a playlist and pick which titles you want. Each becomes its own tracked job under a shared parent, so a single failure never hides in the crowd.

Progress as it happens

Speed, time remaining and the current stage — video, audio, merge, convert — pushed over a WebSocket. No polling, and no wondering whether it is still alive.

A real library

Browse, rename, drag between folders, select with Ctrl or a rectangle, pull a whole folder down as a ZIP. Every file operation is confined to one root directory.

Plays in place

A persistent audio bar that survives navigation, and a video player with fullscreen. The volume you set is remembered across both, and across sessions.

For whoever runs the server Hand it to other people without handing over the machine.

Accounts and permissions

Invite people rather than creating accounts for them — they pick their own name and password. Permissions default from a group and can be overridden per person: who may download, keep files, manage the library, or see beyond their own folder.

Everyone in their own space

A confined member works in a folder of their own and sees only their own queue and history. An administrator can widen the view to anyone, and read what each account is using.

Keeps itself tidy

Disk usage at a glance, one-click yt-dlp updates, and a sweep for the leftovers an interrupted download leaves behind. English and French, switchable at runtime.

Install

Two commands, no build

The images are published ready to run, so nothing is compiled on your machine. You need Docker, and that is all.

bash 
$ curl -O https://raw.githubusercontent.com/LeoBdt/Siphon/main/docker-compose.yml
# optional, if 8080 is taken: echo "SIPHON_PORT=XXXX" > .env
$ docker compose up -d

Siphon is then on http://localhost:8080. The compose file is self-contained — all three images carry what they need, so there is nothing else to fetch and nothing to build. Set SIPHON_PORT in a .env file beside the compose file to move it — put your own port where the placeholder is — and DATA_DIR to put the library on a bigger disk.

Or build it yourself

Clone the repository and build the images locally — useful for development, or to run an unreleased change.

bash 
$ git clone https://github.com/LeoBdt/Siphon.git && cd Siphon
$ mkdir -p data && sudo chown -R 1000:1000 data # runs as uid 1000
$ docker compose up -d --build

Before you put it on the internet

Siphon signs people in, locks an account after repeated failures, and offers two-factor authentication — but it does not terminate TLS. On an open port, put it behind a reverse proxy that does, so passwords and session cookies are not sent in the clear.

It is a personal tool for archiving and offline playback. What you may download is governed by each platform's terms and by copyright law where you live; making sure your use is lawful is your call.
